# Mapa da interface iOS e Android

Este documento descreve a arquitetura da tela compartilhada `DebugSwiftAndroidPanel` e das features que ela expõe, comparando-a com o debugger iOS que já existia no projeto. As linhas de features abaixo se referem à rota do painel Skip. A entrada padrão da biblioteca iOS (`DebugSwift.setup().show()`, `DebugSwift.debugViewController()` ou `DebugSwift.App.presentDebugger()`) ainda apresenta o debugger UIKit legado; ela não troca automaticamente para o painel compartilhado.

## Como ler as camadas

| Camada | iOS | Android |
| --- | --- | --- |
| SwiftUI compartilhado | A tela é executada como SwiftUI. | O Skip transpila o SwiftUI para Kotlin/Compose. A tela não precisa de uma segunda implementação visual em Compose. |
| UIKit legado | Na rota Skip, controladores nativos específicos são hospedados por `UIViewControllerRepresentable`. A entrada padrão da biblioteca continua UIKit. | UIKit não existe no Android; a feature usa a tela compartilhada ou uma adaptação nativa Android. |
| Compose e host Android | Não se aplica. | `Main.kt` inicia o host com Compose; Skip transforma as views SwiftUI compartilhadas em Compose. O `DebugSwiftComposeProbe.kt` é o composable específico escrito para instrumentar recomposições, não uma tela do debugger. |
| Serviços nativos | Frameworks e APIs do iOS acessados pelo `DebugSwift`. | APIs Android e integrações em Kotlin, acessadas pelas telas compartilhadas através de `DebugSwiftNativeBridge`. |

O modo do módulo está configurado como `transpiled` em [`skip.yml`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/skip.yml). O código Kotlin gerado pelo Skip fica na saída de build; os arquivos gerados não são a fonte editável da UI.

## Mapa por área e feature

| Área e features | UI no iOS | UI no Android | Implementação nativa / observações |
| --- | --- | --- | --- |
| Painel Skip, categorias e listas | SwiftUI compartilhado quando o app usa `DebugSwiftAndroidPanel` | SwiftUI convertido pelo Skip para Compose | Definidos em [`DebugSwiftAndroidPanel.swift`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/DebugSwiftAndroidPanel.swift). O exemplo Android usa o painel como tela principal em [`DebugSwiftAndroidSampleApp.swift`](../Example/Android/Sources/DebugSwiftAndroidSample/DebugSwiftAndroidSampleApp.swift). |
| Entrada padrão do debugger legado | UIKit: botão flutuante, navegação/tab bar e controladores UIKit via `DebugSwift.setup().show()`, `debugViewController()` ou `App.presentDebugger()` | O módulo Android atual expõe o painel Skip; o exemplo o mostra em tela cheia. Não há nesse módulo um launcher flutuante equivalente ao do iOS. O host deve chamar `AndroidDebugTools.install(application)` para instalar os serviços. | A entrada iOS fica em [`DebugSwift.swift`](../DebugSwift/Sources/Settings/DebugSwift.swift), [`FloatViewManager.swift`](../DebugSwift/Sources/Helpers/Managers/FloatViewManager.swift) e [`TabBarController.swift`](../DebugSwift/Sources/Base/TabBarController.swift). O host Android está em [`Main.kt`](../Example/Android/Android/app/src/main/kotlin/Main.kt); o exemplo de integração está em [`README.md`](../Example/Android/README.md). |
| **Network:** `http`, `websocket`, `network_injection`, `network_thresholds`, `graphql`, `network_encryption`, `har_export`, `webview_network`, `network_history` | SwiftUI compartilhado no painel Skip | O mesmo SwiftUI convertido para Compose | As telas de inspeção e configuração estão em [`DebugSwiftNetworkInspectorView.swift`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/DebugSwiftNetworkInspectorView.swift), [`DebugSwiftWebSocketInspectorView.swift`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/DebugSwiftWebSocketInspectorView.swift) e [`DebugSwiftNetworkInjectionView.swift`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/DebugSwiftNetworkInjectionView.swift). No Android, a captura não intercepta toda a rede automaticamente: o host precisa adicionar o interceptor ao OkHttp, decorar listeners WebSocket e instalar o `WebViewClient` quando quiser instrumentar esses stacks. Veja as integrações Kotlin e o README Android. Histórico/WebSocket também dependem da disponibilidade/configuração da plataforma. |
| **Performance:** `performance_overview`, `performance_widget`, `battery`, `disk`, `memory_warning`, `frame_drops`, `hangs`, `backtraces`, `leaks`, `thread_checker`, `super_calls` | UIKit existente, hospedado por `UIViewControllerRepresentable` no painel Skip | SwiftUI compartilhado convertido para Compose, usando a tela genérica de detalhes | Android obtém dados e executa ações por [`DebugSwiftNativeBridge.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/DebugSwiftNativeBridge.kt) e [`AndroidDebugTools.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/AndroidDebugTools.kt). Há diferenças de cobertura: `disk` não traz ainda a série de taxas, o browser de descritores abertos e as métricas de uso que existem no UIKit; `battery` é uma leitura instantânea, sem o histórico/controle de monitoramento iOS; quedas de frames, hangs, leaks e super calls são diagnósticos Android com métodos/limites próprios, não telas ou algoritmos 1:1. |
| **Interface compartilhada:** `grid`, `touches`, `dark_mode` e controles de bordas (`colorize` no iOS, `view_borders` no Android) | SwiftUI compartilhado | SwiftUI convertido para Compose | A tela de grid e os controles chamam `DebugSwiftAndroidRuntime`; a aplicação do overlay e configurações do host usa implementação nativa. |
| **Interface adicional do iOS:** `animations`, `measurement` | SwiftUI compartilhado | — | No painel iOS, esses itens usam a tela compartilhada de configuração. |

| **View debugger / hierarquia:** view debugger no iOS; `view_hierarchy` no Android | UIKit: `InAppViewDebugger`, aberto pelo gesto de pressionar o botão flutuante do debugger legado; não é uma feature listada no painel Skip | Detalhe SwiftUI genérico convertido para Compose, com captura de hierarquia por Kotlin | O Android apresenta o snapshot de hierarquia como texto; não é o navegador interativo de snapshots da implementação iOS. | **Interface adicional do Android:** `animation_control`, `compose_renders`, `doc_recorder`, `measurement`, `color_palette` | — | Detalhe SwiftUI genérico convertido para Compose | A lógica específica de Android fica em Kotlin. `compose_renders` usa o probe Compose em [`DebugSwiftComposeProbe.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/DebugSwiftComposeProbe.kt); o probe mede recomposições e não desenha a tela de configuração. |

| **App com detalhe genérico:** `device_info`, `push_token`, `custom_actions`, `custom_info` | SwiftUI compartilhado | SwiftUI convertido para Compose | Os dados e ações vêm do framework iOS ou da implementação Android. O token de push é próprio de cada plataforma (APNs no iOS, FCM quando integrado no Android). |
| **App no Android:** `crashes`, `oslog_console`, `location`, `loaded_libraries`, `push_simulator`, `deep_links`, `event_bus`, `agent_debug_log` | — | Detalhe SwiftUI genérico convertido para Compose | A coleta e as ações Android ficam principalmente em [`AndroidDebugTools.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/AndroidDebugTools.kt), com Logcat, intents, bibliotecas instaladas, eventos e APIs do sistema. ## Pontos importantes para avaliar paridade

- `UIViewControllerRepresentable` é a ponte iOS para conservar telas UIKit pontuais dentro da navegação SwiftUI compartilhada. Ela não participa do build Android.
- No Android, Compose é principalmente o resultado da tradução Skip das views SwiftUI. A implementação Kotlin fornece acesso às APIs Android e a recursos que não têm equivalente SwiftUI.
- As telas `DebugSwiftFeatureDetail` são uma apresentação comum de snapshot e ações. Elas dão acesso às operações implementadas para cada feature, mas não oferecem a mesma navegação, controles e organização das telas UIKit de performance, recursos e app. Para essas linhas, a equivalência visual/funcional 1:1 ainda requer evolução específica.
- Revisei o catálogo em `DebugSwiftArea.features`, as rotas de `DebugSwiftFeatureDestination`, os filtros de disponibilidade iOS e o despacho Android em `AndroidDebugTools.snapshot`. Todos os IDs declarados pelo painel estão mapeados acima: 51 entradas iOS e 53 Android antes dos filtros de disponibilidade iOS. Recursos do debugger legado que não são IDs do painel — entrada flutuante, view debugger e controladores extras do host — agora também estão explicitados.
- A lista e a disponibilidade de features variam por plataforma. O iOS filtra recursos conforme APIs, permissões e configurações; o Android inclui ferramentas próprias, como hierarquia View e rastreamento de recomposição Compose. Uma linha identifica uma rota, mas não afirma que as APIs ou a cobertura funcional sejam idênticas.
- A cobertura Android de network requer integração do app hospedeiro com cada stack de rede. Não equivale à captura global do iOS.
- O alvo iOS do pacote está em iOS 16 no [`Package.swift`](../Package.swift). Algumas features mantêm requisitos maiores, como SwiftData no iOS 17.

## Arquivos de referência

- [`DebugSwiftAndroidPanel.swift`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/DebugSwiftAndroidPanel.swift): lista de áreas/features, seleção entre views compartilhadas, detalhes genéricos e hosts UIKit.
- [`Main.kt`](../Example/Android/Android/app/src/main/kotlin/Main.kt) e [`README Android`](../Example/Android/README.md): entrada Compose e setup exigido para integrar o painel/serviços a um app hospedeiro Android.
- [`DebugSwiftNativeBridge.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/DebugSwiftNativeBridge.kt): interface entre o Swift transpilado e os serviços Kotlin.
- [`AndroidDebugTools.kt`](../DebugSwiftAndroid/Sources/DebugSwiftAndroid/Skip/AndroidDebugTools.kt): serviços, snapshots e ações nativas Android.
- [`DebugSwift.swift`](../DebugSwift/Sources/Settings/DebugSwift.swift): disponibilidade de features iOS e factories UIKit para network, app e performance.
- [`DebugSwiftInterfaceSettings.swift`](../DebugSwift/Sources/Features/Interface/DebugSwiftInterfaceSettings.swift) e [`DebugSwiftResourceViewControllers.swift`](../DebugSwift/Sources/Features/Resources/DebugSwiftResourceViewControllers.swift): factories UIKit para interface e resources.
